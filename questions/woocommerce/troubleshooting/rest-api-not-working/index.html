Why Isn't the WooCommerce REST API Responding Correctly?

SHORT ANSWER

The WooCommerce REST API depends on WordPress's permalink structure being set to anything other than "Plain" (which breaks REST routing entirely), correctly scoped API key permissions (read, write, or both) matching what the integration actually needs, and no security plugin or server-level firewall blocking REST API requests specifically. Checking these three in order resolves most "API not working" cases.

Why This Happens

WordPress's REST API (which WooCommerce's own API builds on) relies on proper URL rewriting to route requests correctly, which requires a permalink structure other than the default "Plain" setting. Beyond that, WooCommerce's API keys carry specific, explicitly granted permissions, and various security tools (firewalls, security plugins) sometimes block REST API traffic by default as a blanket security measure, unaware that legitimate integrations depend on it.

Common Causes

  • Permalink structure set to "Plain" under Settings → Permalinks, which breaks REST API routing entirely regardless of anything else being configured correctly.
  • API key permissions insufficient for the specific operation being attempted — a read-only key can't be used for a write/update request, which will fail with an authorization error rather than a generic one.
  • A security plugin or web application firewall blocking REST API endpoints, sometimes as an overly broad default rule not intended to catch legitimate WooCommerce API use.
  • Expired or revoked API keys, particularly if keys were regenerated at some point without updating the integration using the old ones.
  • A caching layer incorrectly caching API responses that should be dynamic, causing stale or unexpected data to be returned.

How to Diagnose and Fix It

  1. Confirm permalinks aren't set to "Plain" first, since this alone can explain a complete API failure.
  2. Check the specific API key's permissions against what the failing request actually needs.
  3. Test the API request directly (via a tool like Postman) outside of the integrating application, to isolate whether the issue is server-side or specific to the integration's own code.
  4. Temporarily disable security plugins on staging to test whether one is blocking REST API traffic.
