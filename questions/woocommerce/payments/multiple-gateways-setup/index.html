Can I Offer Multiple Payment Gateways, and Prioritize Them?

SHORT ANSWER

Yes, and it's a normal, supported setup — most stores offer at least a card gateway (Stripe or similar) alongside PayPal, and often an offline option like bank transfer too. Under WooCommerce → Settings → Payments, every enabled gateway appears in a drag-and-drop list controlling the order they're shown at checkout, so the preferred option can simply be dragged to the top.

ON THIS PAGE

  1. How It Works
  2. Things Worth Considering
  3. Setting It Up Well

How It Works

WooCommerce treats every payment gateway as an independent, self-contained option, and there's no limit on how many can be active simultaneously. The Payments settings tab lists all installed gateways with a toggle to enable/disable each, and a drag handle to reorder them — whatever order they're arranged in there is exactly the order customers see at checkout, top to bottom.

Things Worth Considering

  • Too many options can hurt conversion just as much as too few — most successful stores settle on 2-4 well-chosen gateways rather than enabling everything available.
  • Some gateways can be restricted to specific countries or currencies individually, which is useful for offering a locally preferred payment method only to customers where it actually applies.
  • Gateway-specific fees differ, so the "cheapest for the store" option isn't always the one customers prefer — the two considerations often pull in different directions.
  • The default/top gateway matters more than the rest, since some checkout designs pre-select it, making its position genuinely influence completion rates, not just visual order.

Setting It Up Well

  1. Enable only the gateways actually relevant to the store's customer base, rather than every option available by default.
  2. Order them by actual customer preference data if available (checkout analytics, past order gateway split), not just gut feeling.
  3. Test the checkout flow with each gateway individually after any reordering, since some page-builder or custom checkout templates render the list differently than the default.
