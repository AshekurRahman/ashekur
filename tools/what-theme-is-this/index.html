What this tool checks

Paste in a URL and this tool fetches the site's public homepage — the same page a browser or search engine already loads — and pattern-matches it against known signatures for WordPress itself, six popular page builders (Elementor, Divi, Beaver Builder, Bricks, WPBakery, Oxygen), common themes, and a shortlist of high-signal plugins like WooCommerce, Yoast SEO, Rank Math and WPML. It reads only what's already publicly visible; nothing is logged into, nothing is modified.

How to read the result

Each panel gets a plain-language verdict rather than a raw signature dump. Detected means two or more independent signals matched; Possible means one did — some sites minify their markup or customize things enough that a real builder's signature can be partly hidden. If no builder is found at all, that usually means a fully custom theme built with hand-coded templates rather than a drag-and-drop builder, not that the check failed.

Why this matters if it's your own site

Knowing what platform your own site runs on changes what "normal" maintenance looks like. An Elementor or Divi site depends on that plugin/theme staying updated and compatible with everything else installed — that's usually where a sudden layout break or a stuck editor comes from. A WooCommerce store has an entirely different set of things that can quietly go wrong at checkout. Whichever one this turns up, the result links straight to the service page built for that exact situation.

Why this matters for a site you don't own

If you're looking at a competitor's site or one you admire and wondering what it's built on, this gives a genuine answer in a few seconds — useful before briefing a developer, scoping a similar project, or just satisfying curiosity. Elementor vs Divi is a good next read if the result names one of those two and you're trying to decide between them yourself.

FAQ

Questions about this detector

Is this WordPress theme detector actually free?

Yes. There's no signup, no email gate and no limit on how many sites you can check. Paste a URL and get a result in a few seconds.

How does it know what theme or page builder a site uses?

It fetches the site's public homepage — the same page your browser already loads — and looks for known markup, script and stylesheet signatures: things like /wp-content/themes/divi/, data-elementor-type attributes, or Beaver Builder's fl-builder classes. It's pattern-matching against what's already publicly visible, not a guess.

Why does it say a builder was "possible" instead of "detected"?

Confidence depends on how many independent signals were found. One matching signature shows as possible; two or more shows as detected. Some sites minify or heavily customize their markup, which can hide a signature that would otherwise be obvious.

Can it check any website, or only WordPress sites?

Any public URL. If the site isn't running WordPress at all, the result says so plainly instead of forcing a WordPress-shaped answer onto a site built with something else.

Is it safe to check a site I don't own?

Yes. It only reads what's already publicly visible on the homepage, the same way a browser or search engine already does. It doesn't log in, doesn't modify anything, and can't reach anything that isn't already public.

It detected my site's builder — what should I do with that?

If it's Elementor or Divi and something isn't working the way it should, the result links straight to the right service page for that platform. If you're just curious about a site you admire, that's a fine reason to use it too.
